# ชฎารัตน์ นวดเพื่อสุขภาพ — ระบบจัดการร้าน

ระบบแดชบอร์ดสำหรับจัดการร้านนวดเพื่อสุขภาพ "ชฎารัตน์" (อุบลราชธานี) ครอบคลุมตั้งแต่บันทึกการนวดรายวัน
คำนวณค่าคอมมิชชัน จ่ายเงินเดือนพนักงานแบบงวดครึ่งเดือน ไปจนถึงสรุปรายได้-กำไรของร้าน

เป็นเว็บแอปแบบ Single Page Application เขียนด้วย Vanilla JavaScript (ES Modules) ล้วนๆ ไม่มีเฟรมเวิร์ก
ไม่มีขั้นตอน build ใช้ [Firebase](https://firebase.google.com) เป็นทั้ง hosting, ฐานข้อมูล (Firestore)
และระบบล็อกอิน (Authentication)

ฟีเจอร์ที่ควรรู้เพิ่มเติม:
- **รับประกันค่าแรงขั้นต่ำต่อวัน** — ถ้าค่าคอมวันนั้นไม่ถึงค่าแรงขั้นต่ำที่ตั้งไว้ (และไม่ได้มาสาย/ออกก่อนเวลา) ระบบเติมส่วนต่างให้อัตโนมัติ ปรับยอดขั้นต่ำได้จากหน้าเงินเดือน
- **พาร์ทไทม์จ่ายสดรายวัน** — ไม่เข้ารอบจ่ายเงินเดือนครึ่งเดือนเหมือนพนักงานประจำ แต่ถ้ามียอดเบิกล่วงหน้าค้างอยู่ จะยังโผล่ในหน้าเงินเดือนให้ติดตามได้
- **กล่องค้นหา** — ทุกหน้ารายการ (พนักงาน, การนวด, เบิกล่วงหน้า, การลา ฯลฯ) มีช่องค้นหากรองตามชื่อ/เหตุผลได้

## เทคโนโลยีที่ใช้

- **Vanilla JavaScript (ES Modules)** — ไม่มีเฟรมเวิร์ก ไม่มี bundler, render ด้วย template string + `innerHTML`
- **[Firebase Hosting](https://firebase.google.com/docs/hosting)** — เสิร์ฟไฟล์ static ตรงจากโฟลเดอร์ `public/`
- **[Cloud Firestore](https://firebase.google.com/docs/firestore)** — ฐานข้อมูลหลัก sync แบบเรียลไทม์ทุกหน้าจอ
- **[Firebase Authentication](https://firebase.google.com/docs/auth)** — ล็อกอินด้วยอีเมล/รหัสผ่าน (อีเมลเป็นรูปแบบ `username@project-chadarat.local` ไม่ใช่อีเมลจริง)
- **Google Fonts** — Prompt (หัวข้อ) และ Sarabun (เนื้อหา)

## เริ่มพัฒนาต่อ

ไม่มีขั้นตอน build หรือ dependency ให้ติดตั้ง แก้ไฟล์ใน `public/` แล้วเปิดดูผลได้ทันทีผ่าน local server
ใดก็ได้ที่เสิร์ฟไฟล์ static เป็น ES module ได้ถูกต้อง (เช่น Firebase local emulator หรือเว็บเซิร์ฟเวอร์ทั่วไป)

```bash
# ติดตั้ง Firebase CLI (ถ้ายังไม่มี)
npm install -g firebase-tools

# ล็อกอินเข้าบัญชี Firebase ที่มีสิทธิ์เข้าโปรเจกต์ project-chadarat
firebase login

# รันดูในเครื่องผ่าน Firebase Hosting emulator
firebase serve --only hosting
```

> โค้ดทั้งหมดเป็น ES module (`import`/`export`) — ต้องเปิดผ่าน HTTP server เท่านั้น เปิดไฟล์ `.html`
> ตรงๆ จาก `file://` จะใช้งานไม่ได้เพราะเบราว์เซอร์บล็อก module import ข้าม origin `file://`

## Deploy ขึ้น production

```bash
firebase deploy --only hosting
```

คำสั่งนี้อัปโหลดทุกไฟล์ใน `public/` ขึ้น Firebase Hosting ทันที (ไม่มีขั้นตอน build คั่นกลาง)
เว็บจะอัปเดตที่ **https://project-chadarat.web.app** ภายในไม่กี่วินาที

## โครงสร้างข้อมูลใน Firestore

ทุก collection sync แบบเรียลไทม์เข้า `state` ฝั่ง client ผ่าน `firestore-service.js`:

| Collection | เก็บอะไร |
|---|---|
| `employees` | ข้อมูลพนักงาน (ชื่อ, ประเภท, เงินเดือนตายตัวถ้ามี, สถานะทำงาน) |
| `sessions` | บันทึกการนวดแต่ละครั้ง (ค่าคอม, ราคา, บริการ, มาสาย/ออกก่อน) |
| `advances` | รายการเบิกเงินล่วงหน้า (สถานะ: รออนุมัติ/อนุมัติแล้ว/ปฏิเสธ) |
| `leaves` | รายการลา |
| `deductions` | รายการหักเงินอื่นๆ ที่ไม่ใช่เบิกล่วงหน้า |
| `payroll` | ประวัติการจ่ายเงินเดือนแต่ละงวด (snapshot ยอดสุทธิ ณ ตอนจ่าย) |
| `payrollDeductions` | ยอดหักของแต่ละงวด (ใช้คำนวณยอดเบิกคงเหลือแบบ running balance) |
| `services` | ราคานวดแต่ละประเภท/ระยะเวลา |
| `packages` | ยอดขายแพ็กเกจ |
| `packageTemplates` | เทมเพลตแพ็กเกจที่ตั้งไว้ล่วงหน้า |
| `expenses` | รายจ่ายจิปาถะของร้าน |
| `settings` | ค่าตั้งค่าระบบ (เช่น ค่าแรงขั้นต่ำต่อวัน) |

สูตรคำนวณทั้งหมด (ค่าคอม, เงินประกันขั้นต่ำ, ยอดเบิกคงเหลือ, ต้นทุนพนักงาน ฯลฯ) รวมอยู่ใน `public/js/store.js`
ไฟล์เดียว เพื่อให้ทุกหน้าจอ (แดชบอร์ด, เงินเดือน, ใบสรุปรายได้, หน้าพนักงาน) ใช้สูตรเดียวกันเสมอ ไม่มีตัวเลขหลุดไม่ตรงกัน

## งวดจ่ายเงินเดือน (ครึ่งเดือน)

พนักงานประจำ (นวด/แม่บ้าน) จ่ายเงินเดือนเป็นงวดครึ่งเดือน:

- **H1** = วันที่ 1–15 (จ่ายวันที่ 16)
- **H2** = วันที่ 16–สิ้นเดือน (จ่ายวันที่ 1 ของเดือนถัดไป)

เก็บเป็น key รูปแบบ `YYYY-MM-H1` / `YYYY-MM-H2` ทั่วทั้งระบบ ส่วนพนักงานพาร์ทไทม์ไม่เข้ารอบนี้
เพราะได้รับค่าคอมเป็นเงินสดทุกวันตอนปิดร้านแล้ว

## สิทธิ์การเข้าถึงข้อมูล

กำหนดไว้ใน `firestore.rules` — ทุก collection (ยกเว้น `services` ที่อ่านได้แบบ public) ต้องล็อกอินด้วยบัญชี
ที่มีอีเมลลงท้าย `@project-chadarat.local` เท่านั้นถึงจะอ่าน/เขียนได้ (เป็นชั้นป้องกันเสริมจากฝั่งเซิร์ฟเวอร์
สำหรับบัญชีพนักงาน/แอดมินภายในร้าน ไม่ใช่อีเมลจริงของใคร)
