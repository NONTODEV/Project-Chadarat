# สำรองข้อมูล Firestore ลง Google Sheet ทุกวันตี 1

สคริปต์นี้รันบน Google Apps Script (ฟรี ไม่ต้องเปิด Firebase Blaze plan) ดึงข้อมูลทุก collection
จาก Firestore โปรเจกต์ `project-chadarat` มาอัปเดตแท็บในชีตนี้ให้เป็นข้อมูลล่าสุดเสมอ แล้วก๊อปปี้ทั้งไฟล์
เก็บเป็นสำเนาประจำวันแยกไว้ในโฟลเดอร์ Google Drive ต่างหาก ทุกวันเวลา 01:00 น.

**ทำไมไม่ต้องมี "ตัวซ่อม" อัตโนมัติ**: แต่ละวัน สคริปต์จะ export ข้อมูลฉบับเต็มใหม่ทั้งหมดจาก Firestore
เสมอ (ไม่ใช่การต่อท้ายทีละแถวแบบ log) ดังนั้นถ้ามีการแก้ไขข้อมูลย้อนหลัง (เช่น แก้ยอดนวดของเมื่อ 3 วันก่อน)
ก่อนเวลาตี 1 ของวันถัดไป สำเนาของวันนั้นจะถูกต้องตามข้อมูลที่แก้ใหม่โดยอัตโนมัติ — ไม่ต้องมีอะไรมา "ซ่อม"
ส่วนสำเนาของวันเก่าที่เก็บไปแล้วจะไม่ถูกแก้ย้อนหลัง ซึ่งถูกต้องแล้วตามหลักการเก็บประวัติ ณ จุดเวลานั้น
(เหมือนใบแจ้งยอดธนาคารของเดือนที่ผ่านไปแล้วจะไม่เปลี่ยนตาม แม้จะแก้ไขรายการย้อนหลังในเดือนถัดมา)
ถ้าบางวันอยากบังคับสร้างสำเนาใหม่ด้วยมือ (เช่น แก้ข้อมูลเสร็จแล้วอยากให้สำเนาของวันนั้นอัปเดตตาม)
มีฟังก์ชัน `repairSnapshotForDate` ให้ใช้ — ดูหัวข้อ "ซ่อมสำเนาของวันเก่าด้วยมือ" ด้านล่าง

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

### 1. ให้สิทธิ์อ่าน Firestore กับบัญชี Google ที่จะรันสคริปต์

1. เปิด https://console.cloud.google.com/iam-admin/iam?project=project-chadarat
   (ถ้าเข้าไม่ได้ ให้ล็อกอินด้วยบัญชี Google เดียวกับที่สร้างโปรเจกต์ Firebase นี้ก่อน)
2. กด "GRANT ACCESS" (หรือ "ให้สิทธิ์การเข้าถึง")
3. ช่อง "New principals" ใส่อีเมล Google ที่เป็นเจ้าของ/จะเปิด Google Sheet นี้
4. ช่อง "Role" ค้นหาแล้วเลือก **Cloud Datastore User** (`roles/datastore.user`)
5. กด Save

ขั้นตอนนี้ไม่เกี่ยวกับ Firebase Blaze plan และไม่มีค่าใช้จ่าย — แค่อนุญาตให้บัญชีนี้อ่านข้อมูล Firestore ได้

### 2. เปิด Apps Script ในชีตเป้าหมาย

1. เปิด Google Sheet: https://docs.google.com/spreadsheets/d/1quN__da1wJFS3vyBNLsYjwDVP1zQumykkGVPUR-NubQ/edit
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. จะเปิดแท็บใหม่เป็นโปรเจกต์ Apps Script ที่ผูกกับชีตนี้อัตโนมัติ

### 3. ใส่โค้ด

1. ในหน้า Apps Script กดไอคอนรูปเฟือง **Project Settings** (ด้านซ้าย) แล้วติ๊กถูก
   "Show `appsscript.json` manifest file in editor"
2. กลับไปที่แท็บ **Editor** (ไอคอน `<>`)
3. เปิดไฟล์ `appsscript.json` → ลบเนื้อหาเดิมทั้งหมด → วางเนื้อหาจากไฟล์ `appsscript.json`
   ในโฟลเดอร์นี้แทน → บันทึก (Ctrl/Cmd+S)
4. เปิดไฟล์ `Code.gs` (ไฟล์เริ่มต้นที่มีอยู่แล้ว) → ลบเนื้อหาเดิมทั้งหมด → วางเนื้อหาจากไฟล์ `Code.gs`
   ในโฟลเดอร์นี้แทน → บันทึก (Ctrl/Cmd+S)

### 4. ตั้งเวลาให้รันอัตโนมัติทุกตี 1

1. ที่แถบด้านบนของ Editor เลือกฟังก์ชัน `createDailyTrigger` จาก dropdown (ข้างปุ่ม Debug)
2. กด **Run** (▶)
3. ครั้งแรกจะมี popup ขอสิทธิ์ (Authorization required) → กด **Review permissions**
   → เลือกบัญชี Google ของคุณ → ถ้าเจอหน้าเตือน "Google hasn't verified this app"
   ให้กด **Advanced → Go to (ชื่อโปรเจกต์) (unsafe)** (ปลอดภัย เพราะเป็นสคริปต์ที่คุณเขียนเอง)
   → กด **Allow** (ครั้งนี้จะมีขอสิทธิ์ Google Drive เพิ่มด้วย เพราะต้องสร้างไฟล์สำเนารายวัน)
4. ถ้ารันผ่าน (ไม่มี error ด้านล่าง) แปลว่าตั้งเวลาเรียบร้อย ระบบจะรัน `dailyBackupAndArchive`
   ทุกวันเวลา 01:00–02:00 น. (ตามเวลาที่ตั้งในปฏิทินของสคริปต์ = Asia/Bangkok) โดยอัตโนมัติ

### 5. ทดสอบรันทันที (ไม่ต้องรอถึงตี 1)

1. เลือกฟังก์ชัน `dailyBackupAndArchive` จาก dropdown แทน
2. กด **Run**
3. กลับไปที่แท็บ Google Sheet — ควรเห็นแท็บใหม่ถูกสร้าง: บริการ, พนักงาน, บันทึกการนวด,
   เบิกเงินล่วงหน้า, การลา, รายจ่าย, เงินเดือนที่จ่ายแล้ว, ยอดหักเบิกล่วงหน้า, ตั้งค่า,
   ข้อมูลการสำรอง (เวลาสำรองล่าสุด)
4. เปิด Google Drive — ควรเห็นโฟลเดอร์ใหม่ชื่อ "ชฎารัตน์ - ประวัติการสำรองข้อมูลรายวัน" ข้างในมีไฟล์
   ชื่อ "สำรองข้อมูล {วันที่วันนี้}" เป็นสำเนาทั้งไฟล์ของชีตนี้ ณ ตอนที่รัน

## ซ่อมสำเนาของวันเก่าด้วยมือ

ถ้าแก้ไขข้อมูลใน Firestore ย้อนหลัง (เช่น แก้ยอดนวดของเมื่อ 3 วันก่อน) แล้วอยากให้สำเนาประจำวันนั้น
ที่เก็บไปแล้วอัปเดตตามข้อมูลที่แก้ใหม่ด้วย:

1. เปิดไฟล์ `Code.gs` ในโปรเจกต์ Apps Script
2. หาบรรทัด `var TARGET_DATE = '2026-10-01';` ในฟังก์ชัน `repairSnapshotForDate`
   แก้เป็นวันที่ต้องการซ่อม (รูปแบบ `yyyy-MM-dd`)
3. เลือกฟังก์ชัน `repairSnapshotForDate` จาก dropdown แล้วกด **Run**
4. ไฟล์สำเนาของวันนั้นในโฟลเดอร์ Drive จะถูกลบแล้วสร้างใหม่ด้วยข้อมูลปัจจุบัน

## ถ้าเจอ error ตอนรัน

- **403 PERMISSION_DENIED**: ยังไม่ได้ทำขั้นตอนที่ 1 หรือใส่อีเมลผิดบัญชี — เช็กว่าบัญชี Google
  ที่กด Allow ตอนขอสิทธิ์ (ขั้นตอนที่ 4) ตรงกับอีเมลที่ให้สิทธิ์ `Cloud Datastore User` ไว้
- ถ้ายัง 403 อยู่ ลองเปลี่ยน Cloud project ที่ผูกกับสคริปต์นี้ให้ตรงกับ `project-chadarat` โดยตรง:
  Project Settings → Google Cloud Platform (GCP) Project → Change project → ใส่หมายเลขโปรเจกต์
  `144996454439` (Project Number ของ `project-chadarat`)

## หมายเหตุ

- ชีตต้นฉบับ (ที่เปิดจากลิงก์เดิม) จะถูก**เขียนทับ**ทุกวันให้เป็นข้อมูลล่าสุดเสมอ — ถือเป็น "มุมมองปัจจุบัน"
  ส่วนประวัติแต่ละวันจริงๆ ให้ดูที่โฟลเดอร์ "ชฎารัตน์ - ประวัติการสำรองข้อมูลรายวัน" ใน Drive แทน
  (แต่ละไฟล์คือสำเนาทั้งหมด ณ วันนั้น เปิดดูได้เหมือนชีตปกติ)
- ไฟล์สำเนารายวันจะค่อยๆ สะสมไปเรื่อยๆ (1 ไฟล์/วัน) ถ้าพื้นที่ Drive เริ่มตึง ลบไฟล์เก่าที่ไม่ใช้แล้วได้เอง
  หรือจะบอกให้ปรับสคริปต์ให้ลบไฟล์ที่เก่าเกิน N วันอัตโนมัติก็ได้
- สคริปต์นี้**อ่านอย่างเดียว**จาก Firestore ไม่มีทางเขียน/แก้ไขข้อมูลกลับเข้า Firestore ได้
